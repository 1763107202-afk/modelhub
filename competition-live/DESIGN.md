# MOVE.ARENA Design System
> Version: DS 1.2 · 2026-11-11 · Scope: 江苏科技大学机械创新实验室「智能搬运小车创新挑战赛」
>
> Status: **Design specification / preview phase**. This document does **not** authorize changing live scores, judge logic, or production layout.
> Canonical design candidate: [design-preview-v23.html](./design-preview-v23.html). V21 and V22 remain as earlier comparisons.

## 1. 产品目标

本系统是**真实校内机械创新赛事的现场导播大屏**，不是营销落地页、普通管理员仪表盘，也不是电子游戏场景。现场观众、裁判、待赛选手、主持人应能够在 2–3 秒内识别：**当前轮次和剩余时间 → A/B 赛道队伍与状态 → 得分与用时 → 实时排名 → 下一轮候场与现场广播**。

**核心准则：信息优先、冷静专业、比赛中高辨识度、零冗余、不靠发光/渐变堆砌“科技感”。**

### Inspiration and original art direction

- 参考 [Linear](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/linear.app/DESIGN.md) 的暗色信息层级、密度和细分割线。
- 参考 [NVIDIA](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/nvidia/DESIGN.md) 的工业级直角构图、强对比度和紧凑文字排版。
- 参考 [BMW M](https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/bmw-m/DESIGN.md) 的赛车计时排版、大字号数据与克制的竞技气氛。
- **仅抽取通用设计原则，绝不复制第三方 Logo、专有字体、页面素材或品牌配色。**
- 官方品牌标识仅使用仓库中真实的江苏科技大学机械创新实验室 Logo（例如 \`assets/lab-logo-transparent.svg\`）。

## 2. 不可违反的工程约束（hard requirements）

1. 36 队、18 轮、A/B 两赛道，每轮双赛道。**1920×1080、1521×1258、1366×768** 等桌面大屏必须能在**不滚动**的情况下查看完整 36 队（左右各 18 行），不可单纯缩成 10 队排行榜或自动轮播替代。
2. 必须保证赛事标题、年号、圆形 Logo、轮次、倒计时、两队完整赛事信息、两列榜单、下一轮候场、单行广播在屏幕内部；不得横向溢出、压线、重叠、断字、截断关键分数。
3. **裁判录分页和管理员页不受观众端 CSS 影响**。修改观众端只在屏幕专属根节点内生效。
4. 后端逻辑冻结：实时成绩、裁判独立计时/暂停/停止、计分、同分按完成用时排序、故障补赛、奖项 3/7/8 不得因视觉改版发生变化。
5. 未赛显示抽签签位；已录分显示实际名次和分数；A/B 场上和下一轮候场状态由**真实阶段及队伍数据**计算。前三名仅在有真实成绩时金/银/铜高亮，不给待赛签位发奖牌。
6. \`elapsed_ms\` 未知不能当作 0 秒；用时、得分使用等宽数字；不可只靠颜色表达状态。
7. 初次打开页面、网络断连、模拟数据、积分变化都不可静默伪装成真实比赛状态。仅本地演示能构造模拟成绩，并显示“**演示数据**”。
8. 浏览器 100% 缩放下布局合格；横向或纵向空间不足时优先减小辅助文案和间距，而不是牺牲 36 行的可见性。
9. 不引入依赖外网的商用字体、图标库或图片作为核心渲染先决条件。首屏离线也必须有系统字体回退。

## 3. 视觉语汇（Design Tokens）

### Colors

| Token | Value | 唯一职责 |
|---|---|---|
| \`--ma-canvas\` | \`#080C11\` | 全屏底色（深黑） |
| \`--ma-surface\` | \`#121B23\` | 比赛主舞台与积分榜统一深色 |
| \`--ma-surface-raised\` | \`#1A2731\` | 候场与局部信息层级 |
| \`--ma-border\` | \`#354551\` | 1 px 发丝分割线 |
| \`--ma-text\` | \`#F6F8F8\` | 关键文字、数据 |
| \`--ma-secondary\` | \`#B6C7CF\` | 次级文字 |
| \`--ma-muted\` | \`#718995\` | 未赛/低价值说明 |
| \`--ma-timer\` | \`#FFC178\` | 全场倒计时唯一主要暖色锚点 |
| \`--ma-lane-a\` | \`#32CDA9\` | A 赛道绿 |
| \`--ma-lane-b\` | \`#F0AE63\` | B 赛道琥珀 |
| \`--ma-warning\` | \`#EF965E\` | 倒计时最后30秒 |
| \`--ma-danger\` | \`#E86B68\` | 最后10秒、超时、故障 |

- 不允许出现**整个右榜米白色**，或两侧属于不同视觉系统的情况。
- 色彩比例：约 85% 近黑/暗灰、10% 白色信息、5% 语义强调；不叠加装饰渐变、霓虹泛光、拟物阴影、花哨斜纹。
- A/B 颜色在主赛况、候场、榜单状态之间保持**同一语义**。红色只表示异常/危险，不能用在普通装饰。
- 一律先保证 WCAG AA 文本对比：正常信息建议 ≥4.5:1；超大标题/数字 ≥3:1。

### Typography

- 中文：\`"Noto Sans SC", "Microsoft YaHei", "PingFang SC", system-ui, sans-serif\`，不依赖远端字体加载。
- 数值：\`"Bahnschrift", "Arial Narrow", "DIN Alternate", sans-serif\` + \`font-variant-numeric: tabular-nums\`。
- 桌面大屏参考：赛事标题 28–36 px；轮次 46–68 px；计时 64–82 px（**必须在容器内完整显示**）；A/B 队名 31–48 px；得分 40–60 px；完赛耗时 26–36 px；排行榜行名 12–16 px。
- 字重体系严格收敛：500 常规、650 次重点、750 信息标题、850 极少数赛事主数字。不得大多数元素都 900。
- 中文队名超过 12 字按可用宽度自动降字号，必要时单行省略显示，悬浮/辅助文本保留原始完整队名。屏幕上不自行审查或篡改真实报名名称。

### Spacing and shape

- 基础间距尺度：4 / 8 / 12 / 16 / 24 px；模块间距 10–16 px。
- 面板直角或 2–4 px 小圆角；不使用通篇药丸、圆角大卡片。
- 面板分层依靠背景亮度 + 1 px 线条，不靠厚重黑色投影。
- 所有文本和数字须拥有明确的可用宽度：\`min-width:0\`，配合 \`minmax(0,1fr)\`、\`overflow:hidden\`，禁止固定宽度将榜单挤出可视区。

## 4. 信息架构（1920×1080 标准）

三层主结构：

1. **顶栏**（约 70–84 px）：左原实验室 Logo 与实验室名称／中比赛名称／右时钟及数据同步状态；标题与年份完整显示。
2. **主体**（剩余高度）：左侧约 **56%**，右侧 **44%**；左上中央倒计时及轮次、左中两条 A/B 对战条、左下下一轮候场；右侧 36 队双列计分塔（每列 18 行）。
3. **底栏**（约 40–52 px）：金色/琥珀强调的“现场调度”标签 + 一行通知。长通知单行慢速滚动；短通知静止不动。

**不可把整个左右栏设成超过视口的 \`min-width\`。** 同一 CSS 规则在 1521 px 和 1920 px 下必须成立。行高按可用视口高度均分 18 行；低于 900 px 高度自动紧缩行距和标题。

### Left stage

- “第 01 / 18 轮”与中央倒计时分开；中央时钟区域应留至少 8 px 顶底安全空间，**数字不得与计时进度轨重叠**。
- A/B 两张赛况条为同一轴线，共用队名、得分、用时栏的纵向对齐；主队伍状态占第一阅读层；VS 仅是小型视觉辅助标记。
- 未录分时 \`---\` / \`--:--.--\` 弱化到相对低对比，避免喧宾夺主；一旦录分强高亮，不允许横向数字溢出。
- “等待上场”暖黄，“比赛中”绿色，“已完成”低饱和白色，“故障/违规/急停”红色；**只在真实存在该状态时出现**。
- 下一轮候场队名应明显大于普通排行榜队名，显示对应 A/B 颜色及队伍名称，底部 18 段进度只标记真实轮次。

### Right timing tower

- 36 队左右两列，各 18 行；中间 1 px 线，保留必要微弱斑马纹。
- 待赛行轻量化；进行中标 \`本轮A/B\`，候场标 \`候场\`；已赛显示**得分与用时横向**且可读，必要时缩小字号但不能隐藏核心数字。
- 真实前三名仅用金/银/铜**名次数字的小型描边**，禁止整行巨大金色背景。
- 公开场合展示真实队伍名称应遵守组织方的展示规范；如果另需脱敏，单独指定规则，不能未经授权改动报名数据。

## 5. 动效规范

仅对**真实事件变化**触发，避免持续播放无意义的背景光效。

| Event | Motion | Timing |
|---|---|---|
| 换轮 | A/B 赛道信息轻微平移进入 | 240–400 ms |
| 成绩确认 | 对应数值/排行行短暂高亮 | 300–700 ms |
| 排行名次变化 | 变化行高亮一次，不让36行同时跳动 | 350–600 ms |
| 计时进行中 | 稳定数字刷新与底部细进度轨 | 每秒，等宽数字 |
| 最后30秒 | 改为橙色；最后10秒改为红色，避免强闪烁 | 状态变化 |
| 长广播 | 单行匀速滚动，短文本静止 | 24–40 秒/循环 |
| 颁奖揭晓 | 分层顺序出现 | 250–600 ms |

必须实现 \`prefers-reduced-motion: reduce\`，无动效时信息依然可读。不要出现阻挡裁判操作的全屏动效。

## 6. 状态契约

- \`upcoming\`: **04:00 / 等待比赛开始**，仅为比赛计划时长的展示，不得伪装为已经启动的倒计时。
- \`live\`: 根据**赛事服务端时间戳**计算剩余时间 \`max(0,240-elapsed)\`；0 秒显示“本轮时间到”；最后30秒和10秒分别警示。
- \`retry\`: 单独显示“故障补赛”；如果没有补赛起始时间，**不要推断主计时**。
- \`review\` / \`awards\`: 显示成绩核对/颁奖，不能继续显示 04:00 。
- 赛道用时来自裁判各自独立的 elapsed 记录，和主轮次倒计时概念严格分离。
- 网络状态分 “在线 / 同步重试 / 持续断线”；演示模式明确标识“非正式比赛数据”。

## 7. 验收矩阵（必须真实测试）

| 浏览器可视宽×高 | 必验项 |
|---|---|
| \`1920×1080\` | 36 队两列全可见、无纵横滚动、Logo/标题/计时全可见 |
| \`1521×1258\` | 之前出现过横裁切的重点回归尺寸，绝不允许右榜被挤出屏幕 |
| \`1366×768\` | 18 行高度紧凑但可读，倒计时不能压分隔线 |
| \`1280×720\` | 优先保护核心数据；必要时辅助文案收紧 |
| \`390×844\` | 观众端可纵向阅读；裁判手机端必须单独验收 |

- 检测 \`scrollWidth <= innerWidth\`（桌面）、\`screenRect.right <= innerWidth\`、榜单最后两行 bounding box 在屏幕内、计时器 bounding box 与下边界相离。
- 测试：待赛、正赛 03:20、最后 00:25、00:09、时间到、A/B 用时不同、1/18/36 队录分、超长队名、断网、颁奖。
- **不能使用“浏览器自动化看起来正常”代替真实特定分辨率的截图/像素级验收。**
- 预览通过后才安排将其接入 \`competition-live/index.html\`；不得通过预览点击触发任何云端 RPC。

## 8. 文件与发布规则

- \`DESIGN.md\`：唯一视觉规范源，更新先维护此文件。
- \`design-preview-v21.html\`：隔离的**静态演示/视觉验收稿**，不连接 Supabase，不提交成绩。
- \`index.html\`：正式观众/裁判/管理员系统；此阶段**不修改**。
- 新预览必须是可逆的新文件；回退只需要继续使用正式页面。
- 所有未来 UI 变更必须附：参考的规范章节、影响范围、测试分辨率、截图或浏览器证据、未完成验收项目。

**发布门槛：设计预览验收通过 + 真正的多尺寸回归 + 演示模式赛事流程验收；之后才允许改动生产观众端。**


## 9. V22 风格融合与审美复盘（2026-11-11）

本版综合用户近期提供的 \`ai-design-skills\`、VoltAgent \`awesome-design-md\` / Google Stitch \`DESIGN.md\` 参考，并吸收 V18–V20 实际截图的问题：

- **Linear 的结构性精致**：接近黑色的主背景、少量层级、精确栅格、统一字重，而非泛蓝灰色的大面积卡片。
- **NVIDIA 的工程可读性**：清晰发丝线、接近直角的组件和密集但有秩序的数据排列，不复制 NVIDIA 的绿或品牌。
- **BMW M 的赛事张力**：字体数字成为竞技气质来源，计时居中，队名与分数是主要视觉资产，不引入赛车照片或专属品牌色。
- **用户本人反馈约束**：摒弃左右黑白割裂、计时压线、宽度溢出、重复文字、过强未赛占位符、候场字号太小、观众端长期显示后台按钮等历史问题。
- **动态只奖励真实信息事件**：模拟换轮、分数更新、低于 30 秒和颁奖；预览场景必须明显标出「演示」。
- **结构不可降级**：保留 36 队实时同屏，在 1920×1080、1521×1258、1366×768、1280×720 逐项检查横向溢出和计时器的上下安全区。预览本地布局检查不等同于线上生产回归。

设计审美原则：宁可让辅助信息稍小，也不允许“比赛倒计时”和“实时积分榜”互相挤占。视觉重点由 **对比度、比例、留白、数字节奏和一贯语义** 产生，避免模仿堆砌式 AI 仪表盘。



## 10. V23 — 去模板化 / Editorial Motorsport（2026-11-11）

用户授权大幅调整预览版观众端 UI。此次有意识地舍弃此前不断叠加的组件化仪表盘观感，以「赛事编辑设计 / Editorial Motorsport」作为唯一视觉主线：

- 取消赛道内用于装饰的 A/B 卡片、得分嵌套卡、背景渐变、发光与厚重边框；赛道字母改成排版元素，不再表现为按钮。
- 左右面板统一为深黑/炭灰色调；不再做左黑右白割裂，使用实线和空间而非阴影堆出层级。
- 得分、用时、赛道队名与中央计时器采用三层清晰字阶，不再所有模块都巨大加粗；状态文字安静且具有语义。
- 榜单恢复计时塔的连续 18×2 行结构，优先真实队名与成绩，弱化未赛状态，奖牌仅通过前三名签位数字颜色呈现。
- 候场区域改为无卡片两列，现场播报为单行文字带，演示按钮在主体布局之外。
- 只保留赛况切换的一次性细微过渡和必要的倒计时状态色；尊重 reduced-motion。
- 演示页面 \`design-preview-v23.html\` 独立于生产，保留原36队、原徽标、五种模拟场景和3/7/8奖项；不接云端服务。

交付状态：**V23 是预览候选，未获用户视觉确认时不得替换正式比赛页面。** 仍须在目标投影设备用 100% 缩放核对 1521×1258 与 1366×768 的真实布局，特别是右榜最后一行、中央时钟下沿及长队名。
