# PROJECT NEXUS｜全中文工程工作站

> 当前状态：**Electron Windows 版工程源码已提交，自动编译流程已配置；Windows 完整功能验收尚未完成。** 不应将“已提交源码”视为“已成功构建正式版”。

## 为什么改造

旧版本 Go + PowerShell/WPF 在 Windows 上反复出现 `ShowDialog()` 空引用异常，并且主工程文件入口不明显、聊天响应失败无法正确反馈。新版本采用 Electron 原生 Windows 桌面应用窗口，不再通过 PowerShell 显示 UI，也无需用户配置 Python。

## 已实现源码模块

- 高对比简体中文桌面界面，可全屏显示，支持单独置顶 AI 聊天悬浮窗口
- 新建工程项目与**明确的工程源文件/文件夹抽屉**，一键打开和定位真实磁盘文件，取消映射不删除文件
- 用户明确创建的验收任务与进度统计；**聊天记录不会被自动当成已完成任务**
- 软件启动台：扫描 Windows 桌面与开始菜单快捷方式，根据关键词进行类别推荐、搜索、收藏后启动
- 工作任务看板
- OpenAI / DeepSeek / 通义千问 / 硅基流动 / Ollama / 自定义兼容接口的模型配置和聊天请求；HTTP 错误展示具体原因
- 截取显示器图像，或者粘贴 Win+Shift+S 截图；先预览再主动发送到有视觉能力的模型
- 人工导入 ChatGPT 官方 `conversations.json`，本地存储摘录；**无法在后台读取用户当前 ChatGPT 实时聊天**
- API Key 在 Windows 安全存储加密；工程数据写入本机 Electron 用户数据目录

## Windows 构建

本目录源文件：`main.js`、`preload.js`、`renderer.js`、`index.html`、`package.json`。

GitHub 工作流：[NEXUS Windows 构建](https://github.com/1763107202-afk/modelhub/actions/workflows/nexus-windows.yml)。

在 Windows 环境本地构建：

```powershell
cd project-nexus
npm install
npm test
npm run build
```

构建成功后在 `project-nexus/dist` 下生成安装包和便携版。无需 Python；构建需要 Node.js，运行已编译软件不需要 Node.js。

## 隐私原则

用户的聊天记录、API 密钥、Windows 私有路径和屏幕截图**不进入公开 GitHub 仓库**。截图只有用户主动发送才发往模型服务商；本地映射仅保存引用，不复制、移动或删除原工程。

## V1.5：ChatGPT 官方导出导入及项目长期记忆

- NEXUS 内点击「打开 ChatGPT 官网」，登录后到「设置 → 数据控制 → 导出数据」申请官方压缩包；收到下载链接后下载 ZIP，再点击「导入官方 ZIP / JSON」。第三方应用**不能直接登录读取私人 ChatGPT 云端历史**。
- 直接导入 `conversations.json` 或包含该文件的官方 ZIP；识别重复会话，保留人工设定的项目归属，新增历史提供归属建议、必须由用户确认。
- NEXUS AI 按当前项目保存独立聊天栏；每次调用附带本项目最近对话，可继续追问；可另行编辑项目长期笔记，记录经确认的版本、结论、待办与问题。
- 只有勾选「允许包含历史摘录」才会向模型传送已关联此项目的历史内容，不会把其他项目历史混在一起。
- 历史文本、项目笔记和模型聊天在本机保存；不上传 GitHub；首次导入建议备份当前工作站数据。
- 新增 `nexus-memory.js`、`test-memory.js` 的测试和 `adm-zip` 依赖。请通过 GitHub Actions 的 **最新提交** 下载通过验证的包；旧包不包含这些功能。

**限制**：当前不提供自动刷新 ChatGPT 官网聊天、对导出 ZIP 的自动下载、实时对话同步，也没有实现跨设备同步或无限上下文；长期记忆使用本地按项目关联、检索与摘要片段传送。Windows 打包成功仍需实机验收。

## V1.6：AI 聊天进度评估（人工验收）

在「工程项目 → 项目抽屉 → AI 进度评估」点击「根据聊天评估进度」。应用只检索当前项目在 NEXUS 的本地聊天、长期笔记；若勾选本次历史授权，也会提交已人工关联到当前项目的 ChatGPT 历史摘录给当前选择的 AI 模型。模型给出项目阶段、任务候选、证据文字、可信度和状态，结果保存为 `aiReview` 建议记录。

- 「加入待办」：创建未完成的项目任务；不提升已验收比例。
- 「确认已完成」：仅出现在模型标记为「已完成待确认」的条目上，还需要用户手动确认才能计入验收进度。
- 每个项目独立评估，不跨项目合并聊天；若没有资料，会明确提示无法评估。
- AI 基于聊天的判断不是技术验证或真实工程文件测试结果；项目进度比例仍按用户确认的任务计算。

工程抽屉新增默认打开主工程、按文件类型识别图标；软件启动台调用 Electron 的 Windows 文件图标提取接口，从快捷方式目标加载程序图标。上述功能仍需 Windows 真机验收，GitHub Actions 编译通过不代表所有行为通过验收。

这一轮采用 **统一交付**：同一套 Windows 安装包/便携版中整合工程项目、AI、文件、日志和报告工具。功能并非所有都达到正式验收；版本号为 `2.0.0-beta.1`。

### 验收与安全

运行 `npm test` 对 JavaScript 语法、项目记忆、文件雷达与日志规则进行基础自动验证；GitHub Actions 在 Windows runner 上打包 EXE。**这不等于 Windows GUI 的完整端到端操作验证。**

- 不自动上传私人的 ChatGPT 对话、目录、截图和 API Key 到 GitHub。
- 不无提示清理系统盘、不自动删除源文件、不自动确认完成工程任务。
- 按项目授权 ChatGPT 历史文本给所选模型，不对第三方平台开放 OpenAI API Key。
- 工作模式只打开用户明确选中的关联软件和文件，不替用户点击软件内的危险操作。
- 在使用新的 Beta 安装包前，请备份旧版本用户数据目录；若发现异常可从 GitHub Actions 下载旧构建包。
